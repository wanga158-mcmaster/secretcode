# Foundation: the shared bank of insight

What we understand about the game, built by the contenders' coordinator and its subagents (see
the [contenders charter](../../contenders/README.md)) and readable by everyone. This is the canonical
bank requested by the user on 22 October 2026. It holds knowledge, never code that bots
include: each contender derives its own bot from this bank, in its own direction.

The organizing reference is now [Mathematics of the game and our controllers](mathematics.md):
definitions, lemmas, conditional theorems, source-bound results and applications, with an explicit
dependency graph. It separates proofs within a model, native premises, finite tested refinement
and open obligations. The pages below supply mechanics and evidence; no current contender's C++
correctness, finite-fuel totality, renewal or winning strategy is claimed proved.

These scope labels qualify claims; they are not mandatory gates before useful controller
iteration. Owners may act under an explicitly limited risk model, with bounded counteraction,
actual receipts and native outcome measurements. `Unsupported`/`Unknown` must remain visible
model results rather than silently becoming permanent controller terminals. A complete proof
against every compatible hidden foe is not required before the next runtime discriminator.

## First dependency audit after resuming

The most immediate shared trap is treating a schedule or communicated capture intent as observed
world state. [M52](mechanics.md#m52-capture-intent-and-expired-respawn-deadlines-do-not-prove-availability)
corrects M49 and SDK S6/S10: a disappearing capturer is not evidence of payout, and a respawn timer
reaching zero is only earliest eligibility. Any occupied member spawn can delay respawn indefinitely.
Separate reservation, observation and prediction; never wait forever on a freshly observed unavailable
group. This applies to every doctrine, without prescribing the same assignment or movement policy.

A later static selection audit corrects [P5](maps.md#p5-bossbattles-only-altar-has-one-camp-occupied-approach-tile):
BossBattle's central group is two monoliths worth 400 gems, and only one member occupies the altar's
sole terrain-legal neighbor. Static whole-group path release does not prove both members and capture
are necessary before any tribute. Current one-blocker death, landing and surviving tribute remain
unresolved; E12/E15 retain their old conditional model values without claiming an engine lower bound.
P6 likewise names its modeled walk/dash/crystal graph rather than proving every kit's reachability
or exclusive ownership of an isolated altar. These corrections use pinned data, not new games.

Priority after this correction: action ordering and actual legality for movement, the single cast,
basic attacks, resets, channels and current buffs. A predictive combat model must be calibrated at

## How an entry is written

Each entry has a stable id (M = mechanics, S = sdk, P = maps, E = economy, C = combat, O = online,
G = strategy), so bots' notes can cite it:
```
### E7. One-line claim
Claim: what is true, with numbers.
Evidence: how it was established (probe, engine games, replays, derivation) and where the run,
  script or replay is; coverage (maps, sides, opponents, sample size).
Rests on: entries it depends on (M3, P2).
Status: verified (engine 1.0.2) | measured | model (prediction, with its error) | hypothesis.
Recheck: what would invalidate it (a patch to X, a new map class).
Consequence: the decisions it changes.
```
Wrong entries are corrected or removed (moved under the repository's removal rules), not left to
mislead. A hypothesis is labelled as one. An entry worth most says what it claims, how it was
established, what it rests on and when to recheck it.
